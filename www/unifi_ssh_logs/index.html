Holt Console-Logs per SSH, matched Regex-Alert-Rules und liefert Events / Binary-Sensors. Nicht die offizielle UniFi-Network-Integration.

Diese Seite liegt unter /local/unifi_ssh_logs/. Optional in der Sidebar: Settings → Dashboards → Add dashboard → Webpage (URL dieselbe; panel_iframe gibt es seit HA 2024.11 nicht mehr).

Architektur (SeeCode)

HA Trigger → Coordinator → asyncssh → UniFi Console → Parser → Alerts / Dateien.

Interaktiv (Trace): unifi-ssh-logs-flow.html

Ablauf

  1. SSH: messages, journalctl -u unifi, UniFi-App-Logs (je nach Optionen); optional Support-Bundle
  2. Nur neue Zeilen seit Cursor
  3. Regex-Rules → Bus-Event + Binary-Sensor on
  4. Auto-Clear nach clear_after_minutes oder Button „Clear alerts“
  5. Dateien unter /config/unifi_logs/ + Retention

SSH-Verbindungen (asyncssh) laufen async auf dem HA-Event-Loop; der Import von asyncssh erfolgt im Executor (kein Blocking-Import auf dem Loop).

Authentifizierung

SSH auf der Console aktivieren (UniFi → Settings → Control Plane → Console → SSH).

SSH-Key (empfohlen)

Key /config/ssh/ha-unifi-logs · known_hosts /config/ssh/known_hosts. Public Key → authorized_keys von root@192.168.0.1.

Fehlt der Host in known_hosts → accept-new (einmalig ohne strikte Prüfung).

Passwort via secrets.yaml

unifi_ssh_logs:
  host: 192.168.0.1
  username: root
  password: !secret unifi_ssh_password
  known_hosts: /config/ssh/known_hosts

UI-Config-Flow kann !secret nicht auflösen. UI-Passwörter landen in .storage.

Sicherheit (0.4.1)

  • Pfade (out_dir, Key, known_hosts, Rules) nur unter dem HA-Config-Verzeichnis
  • Events / sample_line / alert_history / Notify: Logzeilen redacted + gekürzt
  • Custom-Rules: Pattern-/Anzahl-Limits (ReDoS); Support-Fetch mit 5‑Min-Cooldown
  • asyncssh-Import im Executor; Download-API nur mit HA-Auth (kein unauth Tab auf /api/…)

Polling & Log-Card (0.4.1)

  • Switch Abruf aktiv / Polling — schaltet den Auto-Abruf ab (Buttons/Service bleiben).
  • Lovelace-Resource: /local/unifi_ssh_logs/unifi-ssh-logs-card.js?v=0.4.1 (JavaScript Module) — nach Updates Query erhöhen / hard-reload
  • Card-Typ custom:unifi-ssh-logs-card — Logliste + Download TXT/CSV per fetchWithAuth
  • API /api/unifi_ssh_logs/files · /api/unifi_ssh_logs/download
  • Safari: Download ggf. als Blob-Tab (Popups erlauben)

Pfad in HA: /config/blueprints/automation/unifi_ssh_logs/unifi_ssh_logs_notify.yaml

Einstellungen → Automationen → Blueprint erstellen → UniFi SSH Logs — Notify on alert (optional rule_id-Filter, Notify-Service z. B. notify.mobile_app_…).

Eigene Rules

/config/unifi_ssh_logs/rules.d/*.yaml — gleiche id überschreibt Defaults.

- id: my_rule
  name: My pattern
  severity: warning
  source: any
  pattern: '(?i)something.?bad'
  enabled: true
  clear_after_minutes: 30

Beispiel-Automation

automation:
  - alias: UniFi WAN down notify
    triggers:
      - trigger: event
        event_type: unifi_ssh_logs_alert
        event_data:
          rule_id: wan_down
    actions:
      - action: notify.mobile_app_…
        data:
          title: UniFi WAN
          message: "{{ trigger.event.data.message }}"

Diagnostics

Einstellungen → Geräte & Dienste → UniFi SSH Logs → ⋮ → Diagnosedaten herunterladen.

Passwort wird redacted; Key-Pfad bleibt sichtbar, Inhalt nicht. Enthält Status, offene Alerts, gekürzte History.
